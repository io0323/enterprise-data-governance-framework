# 不安定なテストの記録

## `test_keyboard_only_flow`(2026-11-09)

**症状**: CI の Playwright で 1 回、`focus did not reach: ... 'sales.internal'` で失敗しました(実行 `42597597618`。再実行で成功)。

**再現**

| 環境 | 条件 | 結果 |
|---|---|---|
| 開発機 | trace なし 60 回 | 1 回失敗(`focus did not reach`) |
| 開発機 | スナップショットなしの trace 300 回 | 3 回失敗(`Business Metadata` の待ちの時間切れ) |
| 開発機 | スナップショットありの trace 60 回 | 失敗なし(記録が重く、時間の関係が変わる) |
| CI | trace あり、なし各 100 回 | 失敗なし(元の失敗は全テストの実行の中で起きた) |

**原因: テストの待ち方です。UI の不具合ではありません。**

検索の送信で `location.hash` はすぐに変わり、再描画はそのあとの `hashchange` で起きます。テストの 2 つの待ち(ハッシュに `q=` がある、`#catalog-results a` がある)は、どちらも**検索前の古い一覧**で成立していました。送信と同じタイミングで、ハッシュは新しいのに一覧は古い 5 件のままであることを確認しています。

その後の Tab は競合に入り、失敗の現れ方は 2 通りあります。

- **Tab を使い切る**: 読み込み中は結果のリンクが無いので、60 回の Tab が尽きます。検索の応答を止めると確実に再現します
- **Enter が空振りする**: 古い一覧のリンクに Tab で移り、Enter を押すまで約 25ms でした。最終的な画面は検索結果のままで、詳細に移っていません。Enter の前に再描画が入り、フォーカスがリンクから本文に移ったためと判断しています(trace の時刻と最終的な画面からの判断で、この現れ方は決定的には再現していません)

UI は設計どおりです。再描画で古い一覧を消し、読み込み中も応答のあともフォーカスは本文にあります。人の操作の速さでは起きません。

**対処**: 検索語に一致する 1 行だけが表示され、フォーカスが本文に移ったことを確認してから Tab を送ります。再試行、固定時間の待ち、skip は使っていません。回帰テスト `test_search_keeps_focus_on_main_while_results_load` は、検索の応答を止めて読み込み中の状態を固定します。

**確認**: 修正後は開発機で 600 回、CI で trace あり、なし各 100 回、連続で成功しました。修正前の失敗率は開発機で約 1% なので、100 回の成功だけでは偶然でも 37% の確率で起きます。CI は修正前も失敗していないので、CI の結果だけでは修正の効果を示せません。

**調べ方**: 手動の CI(`E2E (Repeat)`)か、次の環境変数で繰り返せます。失敗したテストの trace とスクリーンショットだけが残ります。

```sh
EDGF_E2E=1 EDGF_E2E_REPEAT=100 EDGF_E2E_TRACE_DIR=/path/to/dir pytest -q tests/e2e/test_ui.py::test_keyboard_only_flow
```

`EDGF_E2E_TRACE_SNAPSHOTS=1` で DOM のスナップショットも記録します。重いので、競合は再現しにくくなります。

**残っていること**: `Session.go` も、ハッシュを変えた直後にセレクタを待つ同じ形です。失敗の記録は無いので変更していません(2026-11-10 に下で対処)。

## `Session.go` の待ち方(2026-11-10)

`Session.go` はハッシュを代入した直後に要素を待っていました。`test_keyboard_only_flow` と同じ原因で、切り替わる前の画面で成立し得ます。例えば既定の待ち `main h1` は、どの画面にもあります。失敗の記録はありませんが、16 の呼び出し元を個別に直さず、`Session.go` の中の 1 か所で直しました。

遷移が終わったことの判定は次の 3 段です。

1. **ルートの切り替わり**: 再描画は `<main>` を作り直すので、古い `<main>` に印を付け、印の無い `<main>` が現れるまで待ちます。同じハッシュへの移動では再描画が起きないので、この段は省きます
2. **主要な要素の表示**: 呼び出し元が指定した要素が見えること
3. **読み込みの完了**: 読み込み中の表示(`.loading`)が無いこと

**確認**: 回帰テスト `test_go_waits_until_the_new_page_is_rendered` は、hashchange の処理を数フレーム遅らせるスクリプトを注入し、`go()` から戻った時点で新しい画面になっていることを確かめます。元の待ち方に戻すと、このテストは確実に失敗します。`test_ui.py` の全テストを開発機で 20 回(600 件)、CI の `E2E (Repeat)` で 50 回繰り返して、すべて成功しました。

**残っていること**: `Session.go` を通らずに同じ形で待つ場所が 2 つあります。

- `test_lineage_graph_and_redaction`: 深さの切り替えのあと、ハッシュと `svg.lineage` を待ちます。直後の確認は切り替わる前の画面でも通るので、切り替えの結果を確かめていません
- `test_pagination_uses_headers`: 次ページのボタンのあと、ハッシュだけを待ってテストが終わります
